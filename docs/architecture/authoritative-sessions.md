# Authoritative sessions and the normal client

Offline and server-backed play both enter `SnakeScene.create()` and construct the normal renderer, PauseUI, multi-tab SkillTreeOverlay, HUD, ChoicePopup, DatingScenePopup, save browser, fishing overlay, and baseball overlay. The connected-only scene runtime, NPC renderer, and interaction popup have been removed.

## Run and controls

Run `npm run server` and `npm run dev`, then choose Multiplayer -> Server from the title screen. The form validates/remembers the URL and display name. Direct `?server=ws%3A%2F%2F127.0.0.1%3A8787%2Fgame` and in-process `?connection=local` entry points remain available. Servers start running. Guests never resume an administrative pause; only an explicitly authenticated owner can manage world pause or checkpoints. The connection form accepts a normal invite link, remembers your name/address, and can use `VITE_SNAKE_SERVER_URL` as its configured default.

Normal controls and UI apply: movement keys steer the attached snake, Space opens the full pause shell, E/click opens a nearby Actor menu, F starts fishing with a rod beside water, and B starts baseball with a bat. The normal Save and Save/Load buttons operate on the server checkpoint. Leave Server returns to the connection form. Enter respawns a dead attached character without resetting peers.

In multiplayer, pause tabs, NPC conversations, shops, dating, construction, minigames, and turn-step areas hold that player's automatic movement. Peers, Actors, bosses, projectiles, hazards, and environment time keep advancing. A held player remains vulnerable. Manual movement commands validate the authoritative area and current interaction state. Offline play retains its existing world-pause behavior. Explicit session pause/resume remains separate from menu interaction state.

## State and ownership

- `SceneGameClient` retains detached snapshots and supplies synchronous selectors plus acknowledged commands. Reads do not issue network requests. `SceneGameBridge` is a compatibility export.
- `SnakeGame.getSceneClientState()` projects player flags, inventory/equipment, quests, SPECIAL/progression, relationships, Actors, materialized rooms/world objects, atmosphere, construction, cars, followers, and journals. Quest wire data contains descriptions/objectives rather than callbacks. Projection does not consume gameplay RNG or invoke save supplements.
- `SceneReadReplica` privately hydrates a SnakeGame in explicit `client-replica` mode to reuse legacy selectors. Its public view rejects simulation, reset, writes, mutating service methods, and quest callbacks; returned data is detached. Missing rooms cannot generate. The unguarded hydration target never leaves the controller.
- `RemoteSceneSession` supplies the normal scene's legacy snapshot/session interface and rejects attempts to drive clocks or consume simulation RNG. `SnakeScene.updateSimulation()` only sends interaction-state changes and refreshes presentation in remote mode.
- `AuthoritativeGameSession` owns the shared world and ordered command/connection/persistence queue. Its scheduler owns movement, Actor/boss/bullet/hazard clocks, environment time, gardens, vehicles, and minigames. Per-player movement intervals use authoritative equipment and progression modifiers.
- `AuthoritativeProgression` uses the existing SkillTreeSystem and ActionSlotController with headless callbacks. Equipment, SPECIAL, skill purchases, spell bindings/casts, score modifiers, mana, and extra-life decisions publish mirrored state to the normal UI.
- `AuthoritativeVehicles` uses existing car physics/collision helpers. Entry, control input, movement, room transitions, pickups, impact damage, destruction, and exit placement run on server time.
- `AuthoritativeArchaeology` runs the existing Moleman board model on server world time with per-player session ids. Cursor/swap/leave/summary-close commands validate identity and current activity; only authority computes and applies the earned payout, once. The normal excavation overlay renders snapshots and consumes private ordered board events for its existing juice. Death, leaving the room, disconnect, checkpoint load, and respawn clear stale activity state; a held excavator remains vulnerable while peers and world clocks advance. The foreman is a canonical stationary Moleman Actor, preserving species, portrait, personality, and normal dialogue/dating entry.
- `GuildActions` validates discovered-town identity and a nearby live guild contact for wanted reduction, fencing, jobs, and black-market access. Success rolls, prices, stock, and rewards stay authoritative. The normal guild popup remains in SnakeScene; black-market browsing uses the existing ActorShop UI and canonical merchant offers, with each purchase revalidating guild-contact access. Completed or failed jobs reject replay across players.
- `AuthoritativeMinigames` uses FishingRegistry and BaseballRegistry with server RNG and clocks. Clients send start/pull/swing/abort intents, never outcomes. Gear/proximity validation, catch inventory/journal rewards, baseball statistics, and payouts belong to the authority. Existing overlays render snapshots and collect controls.
- `GameInteractionMenus` owns per-player interaction leases, current quest offers, canonical dating scenarios/branches, range checks, availability checks, and stale revision rejection. `ActorIntent`/`datingAction` responses describe authored dialogue and domain results. SnakeScene keeps the normal bark -> QuestPopup -> actor root -> shop/dating/quest flow; it does not render the legacy generic interaction view. `DatingScenarioDirector` chooses and resolves authored scenario content behind the authority using authority RNG.
- `SpecialShopActions` owns validated goblin ward/style/supply/mercenary/quest purchases and butcher sales. Garage and maneuver trainer callbacks submit existing vehicle/world intents; their existing popups remain shared.
- `GameplayOutcome` supplies ordered, player-scoped facts for movement, apple consumption, quest outcomes, and the bounded transient feedback manifest. SnakeGame captures repeated feedback writes in order; sessions drain the outbox, strip consumed effect flags from replica state, and deliver snapshots before outcome events. Both local action steps and remote event handling invoke `presentAuthoritativeOutcome`, reusing normal JuiceManager, notifications, audio, and popup code. Outcome sequence numbers reject replay; reconnect snapshots do not replay old effects. Durable drowning status and client-owned presentation flags remain queryable state.
- Forced wanderers become a durable, tokened `ForcedEncounter` when their authoritative Actor reaches adjacency. It holds that player's movement while world clocks continue. SnakeScene presents the normal approach effect and authored portrait/pages/Accept/Refuse; decisions validate the token and current proximity before calling `resolveRandomEncounter`.
- Room changes are observed centrally when sessions publish state, covering movement, vehicles, and command-driven transitions. Their events carry the destination head position for the normal room transition pulse. Boss events reuse the normal boss presentation handler; snapshot health observations update the boss HUD/music and hit feedback.
- Player snapshots carry bounded cosmetic appearance (palette, hat, and render style). Cosmetics are visual preferences announced through the identity-bound connection, never client-specified gameplay rewards. SnakeRenderer reuses snake segment recipes, directional variants, palette caching, hat recipes, and retained sprite pools for peers, cleaning up pools when players leave view. Retro grid rendering uses the same retained-object seam.
- Moving into another live player's body is an authoritative fatal collision. Player bullets carry shooter identity, can damage any other live player including the primary player, and cannot hit their shooter. Adjacent shots resolve at the muzzle; traveling shots use the shared bullet clock. Damage uses normal health/protection/extra-life handling and private feedback. Connected spawns leave clearance around existing bodies. Bomb fuses advance once on the server hazard clock even while every player's movement is held; blasts damage each player in range and publish effects to players in the bomb's room. Offline bomb timing retains its existing action-step behavior.
- `AtmosphereAudioManager.refresh()` observes atmosphere and presents audio/notices. It never advances the world. Jason defeat payouts/removal happen in SnakeGame before optional scene presentation callbacks. Visual randomness uses a separate presentation generator.

`SnakeGame.runForPlayer()` selects body/flags, inventory, quests, progression, maneuvers, visited rooms, and transient movement state within one shared world. Never return asynchronous work from this synchronous scope. Only the session queue may hold `runForPlayerAsync()` across an await. The server binds command identity to the attached socket. Hosted state now publishes at 10 Hz through the revisioned delta stream; room caches merge incrementally, with state preceding buffered outcomes/acknowledgements. See [server performance](server-performance.md) for fidelity, telemetry, and regression workloads. Player bodies collide through the normal authoritative action result; dead bodies do not block movement.

## Guest identity, reconnects, and presence

`createGameServer()` issues a cryptographically random 256-bit resume token privately in the welcome envelope. The browser stores it under the canonical server endpoint; it never appears in snapshots, presence, or invites. Connection ids remain disposable transport ids. A token reconnects its existing player context, including inventory, progression, cosmetics, body and death state. The initial world character is claimed once and never recycled to the next socket; other characters have random player ids. Reusing a token in another tab replaces the previous socket (code 4001), and superseded sockets cannot issue commands or remove the replacement connection.

`AuthoritativeGameSession` retains disconnected hosted characters, removes their bodies from live simulation/collision, clears activity leases, and restores their previous alive/dead state on resume. No automatic respawn, settlement, or reward is performed. The world continues for connected peers; an empty hosted server does not drive an unattached snake.

`WebSocketGameConnection` retries temporary established-connection failures with capped backoff, retains listeners and the normal scene, and rejects actions while reconnecting without replaying them. Server ping/pong detects broken sockets. Initial failures return to the existing connection form; protocol rejection and another-window takeover are terminal. Reconnect status remains visible in `PartyOverlay`, which reads the existing connections/players snapshot and displays the crew, room coordinates, join/leave/reconnect notices, an invite action, and explicit Leave Server. Invites contain only the public page and endpoint, stripping names, resume tokens, and host keys. Invites open the existing name/connection form.

Tab uses an owned emoticon through the bounded `emote` intent. Authority validates ownership and expires the expression after five seconds of server elapsed time. Snapshots carry the active expression for peer nameplates and the existing local thought-bubble renderer. New guest characters receive the same starting-emoticon initialization as offline characters. Minimap cyan markers show live connected peers in adjacent rooms on the same level; the crew panel gives room context beyond that range.

Host privilege is independent of character identity. Set `SNAKE_HOST_TOKEN` to an owner key of at least 16 bytes and enter it in the connection form's optional owner field. `createGameServer(session, { hostToken })` validates this credential and supplies an explicit trusted privilege to the authority; guest resume tokens alone grant no privilege. The key is stored separately per endpoint, is not embedded in invites, and is revalidated on each connection. Without a configured key all network players are guests. Checkpoint commands, administrative pause/resume, and enabled debug intents require explicit privilege, including for the initial character. Snapshots expose only `permissions.manageWorld`; normal save buttons hide for guests. In-process trusted callers can explicitly grant privilege with the identity parameter of `attachConnection`/`registerConnection`.

## Persistence

`HOST` and `PORT` configure the Node listener, defaulting to `127.0.0.1:8787`. `SNAKE_SAVE_DIRECTORY` overrides `.snake-server-saves`. FileGameSaveStore implements the existing SaveStore contract with atomic JSON replacement. Save/load/delete commands are restricted to the host while connected. The normal SaveLoadMenu receives actual durable checkpoint records through RemoteCheckpointBrowser. Clients never upload replacement save state. Host checkpoint loads preserve attached guest characters and clear stale activity/control runtimes. Resume identities and retained guest characters last for the running server process; persistence across a server restart remains future work.

## Scope still requiring migration

The shared client architecture and the command paths listed above are implemented; this is not yet parity for every specialty feature in the repository. Offline gameplay still uses its legacy scene authority adapter. Starting faith/background/class offer generation, the complete Starforged/killstreak/radio/Minecraft feature behavior, specialty arcade and remaining scene-owned services still need headless command integration. Minecraft crafting remains part of the pending Minecraft subsystem migration; normal cooking and alchemy brewing already submit inventory/world intents. Remote mode registers score, coordinates, and bonus-apple presentation; it does not run the remaining scene gameplay features against the replica. Unsupported replica mutations fail explicitly instead of inventing browser authority. Resume identities and retained guest characters last for the running server process; persistence across a server restart remains future work.

## Verification

`sceneReadReplica.test.ts` checks hydration, detached reads, guarded mutations/quest callbacks, and missing-room rejection. `sceneGameClient.test.ts` covers mirror purity, player isolation, bounded commands, construction/relationships, debug authorization, continuing hazards/peers during menu holds, and WebSocket identity binding. `authoritativeSceneGameplay.test.ts` exercises manual areas, cars, minigame outcomes/rewards, extra lives, and guest-preserving checkpoint loads without Phaser.

`clientParity.smoke.spec.ts` boots two normal browser clients, renders every available pause tab, verifies player-only holds, equips/uses items through the authority, saves through the normal Save button, loads the server checkpoint while retaining a guest, and opens/controls the existing baseball/fishing overlays. The other multiplayer browser tests cover named connections, independent movement, NPC rendering, shop stock races, private quest acceptance, hotkey isolation, and disconnect/retry. These checks establish the listed behavior, not complete parity for the remaining specialty systems.

`presentationOutcomes.test.ts` verifies ordered single-use feedback, forced encounter holds/token validation, canonical dating choices, player collision death, owned gun damage, cosmetics validation/isolation, and bomb timing/damage while menus hold all snakes. Browser tests drive the authored bark/root/shop/quest flow, confirm peer snake textures and hats, and observe real JuiceManager calls for forced approach, wall chomp without replay, movement, and room transition. Development-only trace instrumentation forwards every observed call to the real JuiceManager.

`specialtyServices.test.ts` covers private excavation boards, authority time and real earned rewards, stale and replayed controls, disconnect/reconnect cleanup, death cancellation, foreman identity, guild costs/proximity/stock access, and cross-player job replay rejection. `specialtyServices.smoke.spec.ts` drives the existing excavation and guild/black-market screens over WebSocket, including cursor/swap juice, peer movement during excavation, the normal summary, and Moleman dialogue.

`persistentParty.test.ts` covers opaque identity/state retention, death preservation, permission separation and revocation, takeover, shared expiring emoticons, and real-socket automatic reconnect. `persistentParty.smoke.spec.ts` covers invite/name entry, refresh, inventory retention, crew notices, normal Tab emoticons, a severed socket, and explicit leave in real browsers with separate storage.

Short socket interruptions use the existing authority with a bounded input replay and isolated client presentation; see [movement reconnects](movement-reconnect.md).

Operational evidence for stalls and connection failures is described in [server logging](server-logging.md).
