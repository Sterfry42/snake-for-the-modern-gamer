# Snake Encyclopedia

> A searchable filing cabinet for existing systems, features, helpers, registries, and abstractions.
>
> **Before implementing new functionality:** search this document first. Prefer targeted `rg` queries such as `rg -n "pause|spotify|youtube|embed" "docs/core/Snake Encyclopedia.md"` rather than loading the whole file into context. If the repo already has the behavior or a close abstraction, reuse or extend it instead of adding a parallel implementation. When a new reusable feature/helper is added, add an entry here.

## Entry format

`Thing [Type]: Description. Usage Notes. Link.`

This is intentionally organized by game concept rather than directory tree. The goal is to answer **“does Snake already know how to do this, and where?”** quickly.

### Consolidation workflow

Consolidation entries are active cleanup leads, not permanent lore. When a consolidation target or candidate is actually resolved in code, remove the resolved line from the **Consolidation Targets** section and update the relevant normal entry so future agents know the new canonical implementation. Do not remove **Navigation Hazard** entries just because they are annoying; those are discovery warnings and should stay until the underlying naming/behavior trap no longer exists.

### Current scope

This reference focuses on reusable runtime/gameplay systems, concrete content definitions, and the places an agent is most likely to accidentally duplicate functionality. It is intentionally a living index rather than a frozen architecture document. Entries marked **Consolidation Target**, **Consolidation Candidate**, **Navigation Hazard**, **Definition-Only**, **Special-Only**, or **Disabled** are especially important.

## Core Feature Tenets

### 1. Systems, Not Special Cases

**The game aims to be systemic. Shared concepts should resolve through unified sources of truth, allowing systems to interact without knowing each other's implementation details.**

A system should consume the shared concept it needs — damage, protection, relationship state, spawn policy, derived stats, capabilities, and so on — rather than inspect every perk, item, NPC type, biome, or feature that might contribute to it.

### 2. The Game Is Made of Verbs

**Game behavior should be expressible as reusable verbs. Verbs may be action verbs, interaction verbs, or passive/reactive verbs. External conditions determine when a verb is available, what activates it, and what deactivates it.**

- **Action verbs** are things an actor deliberately does: Move, Attack, Cast, Drive, Fish, Dig, Use.
- **Interaction verbs** are things an actor does with or against another entity: Talk, Shop, Gift, Romance, Threaten, Pickpocket, Parley, Eat, Spare.
- **Passive verbs** are behaviors that occur in response to state or events: Regenerate, Revive, Protect, Follow, Flee, Decay, Heal, Trigger Frenzy, Gain Momentum.

**Capabilities expose verbs; conditions gate them; systems execute them.** New content should prefer composing existing verbs over inventing bespoke interactions.

### 3. Content Configures Systems

**Prefer definitions, registries, tags, capabilities, modifiers, and shared state over content-specific implementation code. Content describes what it is; systems determine what that description means.**

A new item should ideally grant an existing modifier or capability. A new skill should affect a shared derived stat or known system. A new NPC should expose existing verbs and behaviors. Bespoke code is appropriate when the content is genuinely unique, but it should still compose existing primitives wherever possible.

### 4. Show the Game, Don't Explain It

**Snake is a game of discovery. Communicate mechanics, state, consequences, and changes through gameplay and presentation whenever possible. Prefer visible state, timers, animation, sound, effects, world changes, character behavior, and events over notifications or explanatory text. Text is a fallback when the game cannot communicate something clearly on its own.**

Do not respond to every new mechanic by adding a toast, popup, tutorial paragraph, or status message. If the player can understand something by watching it happen, let them discover it through the game.

## Development Rule: Extend Before You Invent

**Before creating a new system, abstraction, state store, helper, modifier, interaction, or behavior, search this reference and the repository for the existing concept first. Extend or reuse it when possible.**

If the abstraction is genuinely missing, create it intentionally as a reusable source of truth and migrate related behavior toward it rather than adding another isolated implementation.

## Runtime & Composition

- **Browser Entrypoint `[Runtime]`:** Bootstraps Phaser, debug runtime, the default game config, and `SnakeScene`. **Usage Notes:** Use this for application boot/configuration changes, not gameplay rules. **Link:** [`src/main.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/main.ts).
- **Snake Scene `[Integration / UI]`:** The very large Phaser scene that wires input, overlays, rendering, Archipelago, save/load UI, cheats, and many `SnakeGame` calls together. **Usage Notes:** Treat this as an orchestration/integration layer. Before adding reusable behavior here, search for a dedicated system/helper first. **Link:** [`src/scenes/snakeScene.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/scenes/snakeScene.ts).
- **Snake Game `[Core / Integration]`:** The authoritative local gameplay object coordinating snake state, rooms, enemies, animals, quests, relationships, hazards, inventory, progression, and many bespoke features. **Usage Notes:** This is still a major ownership boundary, but it also contains several one-off implementations. Prefer dedicated modules when one already exists; use `SnakeGame` for cross-system orchestration. **Link:** [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Game Configuration `[Config]`:** Defines grid, snake, world, apples, atmosphere, quests, feature toggles, character/raccoon settings, and the default configuration. **Usage Notes:** Add tunable game-wide defaults here rather than scattering constants through scene code when the value is genuinely configuration. **Link:** [`src/config/gameConfig.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/config/gameConfig.ts).
- **Feature Manager `[Abstraction]`:** Wraps the feature registry and invokes enabled feature hooks. **Usage Notes:** Use this to enable/dispatch hook-based features; do not manually call a feature definition from unrelated gameplay code. **Link:** [`src/systems/features.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/features.ts).
- **Feature Registry `[Registry]`:** Dynamically loads `features/definitions/*.ts`, deduplicates features, and exposes lifecycle hooks. **Usage Notes:** New lightweight hook-based features should register through the definitions directory so discovery remains automatic. **Link:** [`src/features/featureRegistry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/features/featureRegistry.ts).
- **Feature Base Class `[Abstraction]`:** Defines reusable feature hooks such as register, action step, tick, render, apple eaten, and game over. **Usage Notes:** Use this extension mechanism for opt-in features that naturally fit these hooks; deeper stateful subsystems may deserve their own service. **Link:** [`src/features/feature.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/features/feature.ts).
- **Simulation Scheduler `[Core Helper]`:** Runs named fixed-interval simulation clocks with delta clamping, catch-up limits, manual stepping, and diagnostics. **Usage Notes:** Reuse this for recurring simulation clocks instead of inventing another accumulator/timer loop. **Link:** [`src/systems/simulationScheduler.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/simulationScheduler.ts).

- **Player Health `[Core]`:** Player heart state is maintained by `SnakeGame`, with max health influenced by progression and multiple hazard/combat paths mutating current health. **Usage Notes:** Read/write health through existing `SnakeGame` methods where available. - **Player Healing `[Helper]`:** `healPlayer()` clamps healing to maximum health and emits the appropriate state/debug changes. **Usage Notes:** Use the existing healing path instead of direct `player.health += ...` mutations. **Link:** [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Player Damage Application `[Core / Consolidation Candidate]`:** Damage is currently applied in multiple separate branches for bombs, lightning, temperature, bullets, melee/enemy hits, animals, and other hazards. **Usage Notes:** There is no single canonical `applyPlayerDamage()` yet. Do not create another bespoke health decrement if an existing branch/helper can be reused; this is a priority consolidation target. **Link:** [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Collision Protection `[Helper]`:** Normalizes immortality, invulnerability ticks, phase state, wall/body phasing, and swim-without-breath checks. **Usage Notes:** Prefer these queries over reading `cheat.immortal`, phase flags, or invulnerability flags directly. **Link:** [`src/systems/protection.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/protection.ts).
- **Unified Invulnerability Ticks `[Helper]`:** Combines Fortitude invulnerability and bullet-invulnerability state into one effective tick count. **Usage Notes:** Use this when a mechanic asks whether temporary invulnerability is active instead of checking only one source. **Link:** [`src/systems/protection.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/protection.ts).
- **Immortal Cheat `[Cheat / Survival]`:** The `immortal`/`mammamia`/`starman`/`mario` cheat grants lethal protection plus full heat/cold resistance and swimming behavior. **Usage Notes:** Cheat aliases belong in the central cheat registry; protection consumers should route through protection helpers. Direct immortal checks still exist and should not be multiplied. **Link:** [`src/cheats/cheatRegistry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/cheats/cheatRegistry.ts), [`src/systems/protection.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/protection.ts), [`src/scenes/snakeScene.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/scenes/snakeScene.ts).
- **SnakeGame Immortality Check `[Compatibility / Consolidation Candidate]`:** `SnakeGame.isImmortal()` directly reads the immortality cheat flag and is used by several lethal paths. **Usage Notes:** Do not add a fourth interpretation of immortality. Prefer converging new protection checks on `systems/protection.ts`. **Link:** [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Death Prevention / Revival Funnel `[Core / Consolidation Candidate]`:** `SnakeGame` coordinates Phoenix-style restoration, wards, extra-life behavior, companion rescue, Arcane Veil, growth-based survival, and other lethal-hit exceptions. **Usage Notes:** Before adding any new resurrection/immortality mechanic, trace the existing lethal ordering here. - **Phoenix Revival `[Survival Feature]`:** `tryFortitudePhoenix()` restores a pre-death snapshot, consumes Fortitude/equipment Phoenix charges, restores health, and grants post-revival protection. **Usage Notes:** Use the existing Phoenix charge path for one-shot revival effects instead of item-specific resurrection code. **Link:** [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).

## Stats, Derived Attributes & Progression

- **Derived Stats `[Abstraction]`:** Resolves durable gameplay-facing values such as max health, action-step scalar, mana, pickup radius, companion capacity, spell slots, life capacity, nutrition, ward duration, stored vitality, and shop pricing from named sources. **Usage Notes:** This is the preferred boundary for progression systems. Skills/classes/backgrounds/equipment-like progression should modify derived stats where a suitable stat exists; consuming systems should read the resolved value rather than inspect the originating perk. **Link:** [`src/stats/derivedStats.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/derivedStats.ts).
- **Derived Stat Breakdown `[Debug / Helper]`:** Provides source-by-source additive/multiplicative breakdowns for a derived stat. **Usage Notes:** Use this for tooltips/debugging rather than recomputing modifier math in UI. **Link:** [`src/stats/derivedStats.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/derivedStats.ts).
- **Generic Modifier Atoms `[Abstraction]`:** Represents typed modifiers from SPECIAL, skills, equipment, apples, statuses, zones, artifacts, quests, and cheats with add/multiply/set/max/min operations and optional priority/expiry. **Usage Notes:** Use this generic resolver when a domain needs composable transient modifiers that do not already fit the durable `DerivedStatResolver` API. **Link:** [`src/stats/modifierResolver.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/modifierResolver.ts).
- **Runtime Equipment Modifier Accumulator `[Abstraction]`:** Aggregates equipment/runtime effects including speed, radiation, senses, invulnerability, resistances, Phoenix charges, light, masonry, gun/tool flags, swimming, regeneration, and refunds. **Usage Notes:** Reuse this accumulator for equipment-like modifier sources. Note that it overlaps conceptually with generic modifiers/derived stats; avoid creating a fourth modifier framework. **Link:** [`src/stats/gameplayModifierAccumulator.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/gameplayModifierAccumulator.ts).
- **SPECIAL Stats Service `[Core / Stats]`:** Owns committed/preview SPECIAL values, point allocation, restore/save normalization, permanent modifiers, and access to SPECIAL-derived sub-modifiers. **Usage Notes:** Use this service to read or change SPECIAL rather than modifying raw stat objects in feature code. **Link:** [`src/stats/specialStatsService.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/specialStatsService.ts).
- **SPECIAL Types `[Data]`:** Defines Strength, Perception, Endurance, Charisma, Intelligence, Agility, and Luck identifiers/types. **Usage Notes:** Reuse these IDs in stat-aware systems rather than string-literal variants. **Link:** [`src/stats/specialTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/specialTypes.ts).
- **SPECIAL Gameplay Modifiers `[Modifier Mapping]`:** Maps SPECIAL deltas into movement, hearts/invulnerability, hazard resistance, melee, weapons, economy, loot, mana, spell slots, nutrition, pickup radius, and companion capacity. **Usage Notes:** If a system should scale from SPECIAL, first check whether a target already exists here. Prefer consuming the mapped modifier/derived value instead of checking raw SPECIAL directly. **Link:** [`src/stats/specialGameplayModifiers.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/specialGameplayModifiers.ts).
- **Level Progression `[Progression]`:** Defines lifetime-score leveling, the cubic score curve, level lookup, level-up results, and normalized progress views. **Usage Notes:** Use these helpers for account/run level calculations rather than duplicating score thresholds. **Link:** [`src/stats/levelProgression.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/stats/levelProgression.ts).
- **Skill Catalog `[Registry]`:** Canonical data registry for all skill-tree perks, branches, prerequisites, costs, effects, migration aliases, tags, and usage hints. **Usage Notes:** Define new skill nodes here and express effects through derived modifiers/known flags/effect types. Do not bury a new perk definition in scene code. **Link:** [`src/systems/skillCatalog.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/skillCatalog.ts).
- **Skill Tree System `[Progression]`:** Owns perk ranks/purchases, effect application, mana, extra lives, score modifiers, and derived-stat synchronization. **Usage Notes:** Use this as the rules layer for purchased skill behavior/state. **Link:** [`src/systems/skillTree.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/skillTree.ts).
- **Skill Tree Manager `[Integration / UI]`:** Scene-facing adapter around the skill tree, action slots, overlay integration, and derived-stat refresh. **Usage Notes:** Use for UI/scene integration; core perk definitions and effect semantics belong in the catalog/system. **Link:** [`src/systems/skillTreeManager.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/skillTreeManager.ts).

## NPCs, Actors, Relationships & Dating

- **Actor Domain Types `[Core / NPC]`:** Defines persistent actor identity: kind, role, species, personality, mood, needs, opinions, memories, social links, health, combat profile, player-hostility state, targeted threat state, authoritative presence, schedule/base goal, active goal stack, activity, brain, soul/lore, speech, and save data. **Usage Notes:** For persistent/world-aware people and creatures, use the Actor model instead of inventing another NPC state shape. Faction hostility toward another Actor belongs in `targetedThreat`/`attackActor`; player-directed aggression belongs in `playerHostility`. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts).
- **Actor System / Lifecycle `[Core / NPC]`:** `ActorSystem.tick(context)` is the single runtime simulation pass reached from the scheduler's Actor clock. It processes dirty schedules, loaded-room environment/brain adapters, local faction conflict, coarse offscreen travel, speech expiry, and one aggregate performance record. Content creation is separate through `ensureActorsFromRoomContent()`, materialization is an explicit loaded-room boundary, and `getActor()`/`getActorsInRoom()` are pure reads. **Usage Notes:** Never advance Actor simulation from a getter, renderer, minimap provider, debug snapshot, interaction query, or serializer. Other systems should use named Actor mutations so semantic no-ops do not rewrite registry state or emit transition telemetry. **Link:** [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts), [`src/actors/actorRegistry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorRegistry.ts), [`src/systems/simulationScheduler.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/systems/simulationScheduler.ts).
- **Actor Brains `[AI Helper]`:** Produces intents to hold, wander, flee threats, approach social links, or share rumors based on role, fear/stress, danger, memories, bond strength, rumor opportunity, and relationships. Stationary/post actors can still talk to adjacent social targets without abandoning their post. **Usage Notes:** Extend common NPC decision-making here rather than embedding movement decisions in each NPC feature. **Link:** [`src/actors/actorBrains.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorBrains.ts).
- **Actor Presence / Occupancy `[Core / NPC Simulation]`:** Centralizes materialized Actor presence, movement reservation, adjacent social stops, schedule goal selection, offscreen travel, room-exit targeting, canonical Activity inference, and faction-conflict target selection. `SnakeGame` seeds Actors from authored room content and materializes legacy NPC-body adapters only when a room/content/presence boundary marks that room dirty; ordinary reads and Actor ticks do not rebuild every body. Authored spawn coordinates are creation-only and must not reset existing Actors. **Usage Notes:** New NPC movement, scheduling, and visible activity behavior should use this module instead of adding local occupied-set, room-travel, or role-inference logic. **Link:** [`src/actors/actorPresence.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorPresence.ts), [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Actor Scheduling `[Core / NPC Simulation]`:** Schedule evaluation writes `Actor.scheduleGoal` as default/base intent and only replaces the active goal when no higher-priority runtime goal owns the Actor. Content-authored phase routines pair a preferred behavior (`forage`, `seekDen`, `ambush`, `work`, and so on) with a common Actor goal; civilians, animals, enemies, and other persistent Actors can therefore share the scheduler without inheriting town-resident assumptions. Scheduled Actors are marked dirty at creation/load and on day-phase invalidation, then evaluated once; unchanged base/active goals produce no registry mutation or telemetry. **Usage Notes:** Configure temporal behavior through `ActorSchedule.routines`, keep moment-to-moment decisions in the Actor brain, and use active goals for interrupts such as threats. Never resolve schedules from renderers, room getters, or constant polling. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/actors/actorPresence.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorPresence.ts), [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts).
- **Actor Combat Interface `[Core / NPC Combat]`:** Actor-vs-Actor conflict stores targeted threat and `attackActor` goals on Actors while combat execution applies damage to Actor health. Faction conflict must not create player-hostile `npc-hostile` shells or set global player hostility. **Usage Notes:** Treat `EnemyInstance` hostile humanoids as a compatibility combat shell only for explicit player-hostile/legacy encounters; do not duplicate persistent humanoid identity there. **Link:** [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts), [`src/game/snakeGame.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/game/snakeGame.ts).
- **Actor Telemetry `[Debug / Performance]`:** Emits structured `actor.*` events only for meaningful state transitions plus one compact `actor.tick` aggregate per Actor clock pass (`durationMs`, populations, brains, schedules, movement, conversations, combat, materialization, and registry mutations). Slow-tick warnings are rate-limited. **Usage Notes:** A `goal_changed` event with equivalent goals is a lifecycle bug; use the aggregate tick counters to profile bounded simulation work without per-Actor polling spam. **Link:** [`src/actors/actorTelemetry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTelemetry.ts), [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts).
- **Actor Navigation `[Core / NPC Simulation]`:** Provides the reusable grid-path primitive for Actor local movement around blocking tiles toward doors, targets, posts, or interaction positions. **Usage Notes:** Use this shared BFS path helper for Actor movement instead of role-specific steering/pathfinding. **Link:** [`src/actors/actorNavigation.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorNavigation.ts).

### NPC Representation: Which Piece Is Which?

A useful mental model is that an NPC's **identity/state** and its **presentations** are separate. A room resident or authored encounter supplies immediate content and placement; `Actor` is the persistent world-aware identity; romance adds `RelationshipState`; and UI chooses a world sprite, a small dialogue portrait, or a large dating portrait depending on the surface. The current `portraitId` field crosses several of these layers, but it is **not one universal image/texture key**.

- **NPC World Body / Map Sprite `[NPC Presentation]`:** World-scale NPC visuals are the small sprites standing on the room grid. `questGiverSpriteRecipe` is a generic runtime-generated body recipe with idle/blink variants and a palette, while special entities can use other sprite recipes. **Usage Notes:** This answers “what do I see walking/standing in the room?” It is not the face in the dialogue box and not the dating portrait. **Link:** [`src/ui/spriteRecipes/questGiverRecipe.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/spriteRecipes/questGiverRecipe.ts), [`src/ui/runtimeSpriteFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/runtimeSpriteFactory.ts).
- **Small Dialogue Portrait `[NPC Presentation / Dialogue]`:** `QuestPopup` displays an 88px portrait generated from the 16x16-style `questPortraitRecipe`. Supported variants include `sage-1/2/3`, bandit neutral/hostile, cardwright, goblin happy/neutral/hostile, and ocean-fisher neutral/happy. **Usage Notes:** This is the **little pixel face beside ordinary dialogue boxes**. It is a different renderer/asset vocabulary from the world body and dating art. **Link:** [`src/ui/questPopup.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/questPopup.ts), [`src/ui/spriteRecipes/questPortraitRecipe.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/spriteRecipes/questPortraitRecipe.ts).
- **Dialogue Portrait Resolver `[NPC Presentation / Compatibility]`:** `QuestPopup.resolvePortraitKey()` converts speaker `portraitId` hints into its small supported portrait variants. It recognizes direct variants plus aliases such as thief -> bandit, guard -> hostile bandit, shopkeeper/villager -> `sage-2`; unknown IDs fall back to `sage-1`. **Usage Notes:** A `portraitId` on an NPC or voice line may be a semantic/legacy hint rather than an actual texture key. When a portrait looks “wrong,” inspect the resolver before creating another asset. **Link:** [`src/ui/questPopup.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/questPopup.ts).
- **Large Dating Portrait `[NPC Presentation / Relationships]`:** Dating uses full-screen/high-resolution portrait assets from `datingPortraitManifest.ts`, including mood families for humans, goblins, angels, goblin-angels, and Molemen. `DatingScenePopup` chooses the asset from the relationship candidate plus current mood. **Usage Notes:** This is the **large portrait used on the romance/dating screen**. It is intentionally a separate art surface from the small pixel dialogue portrait. **Link:** [`src/relationships/datingPortraitManifest.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/datingPortraitManifest.ts), [`src/ui/datingScenePopup.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/datingScenePopup.ts).
- **Generated Dating Portrait Fallback `[NPC Presentation / Fallback]`:** If no loaded dating SVG matches, `DatingScenePopup` generates a 512px portrait through `datingPortraitRecipe` and `RuntimeSpriteFactory`. **Usage Notes:** This is a fallback for the dating presentation, not the small dialogue portrait generator. **Link:** [`src/ui/spriteRecipes/datingPortraitRecipe.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/spriteRecipes/datingPortraitRecipe.ts), [`src/ui/runtimeSpriteFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/runtimeSpriteFactory.ts).
- **NPC Content / Profile Record `[NPC Content / Legacy Compatibility]`:** `NpcProfile` is the lightweight stat/content shape used by many houses, settlements, wanderers, and town residents: name, simple role/encounter type, optional `portraitId`, SPECIAL-like NPC stats, and max hearts. **Usage Notes:** Treat this as authored/generated content feeding richer runtime systems, not as the canonical persistent social brain. **Link:** [`src/npcs/profiles.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/npcs/profiles.ts), [`src/world/town.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/town.ts).
- **Actor Identity `[Core / NPC Identity]`:** `Actor` is the richest persistent “person in the world” record: stable ID, role/kind/species, location, personality, mood, needs, opinions, social links, memories, health/combat, hostility, soul/lore, schedule/brain, flags, and optional portrait/voice hints. `ActorSystem.syncRoom()` promotes town residents, loose NPCs, animals, enemies, and relationship candidates/states into this registry. **Usage Notes:** When a feature needs to remember what an NPC knows, feels generally, witnessed, or is doing across rooms, start with Actor. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts).
- **Relationship Record `[Core / Romance State]`:** `RelationshipCandidateProfile` describes a possible romance; `RelationshipState` owns the romance-specific durable state: stage, affection/trust/jealousy/resentment/fear/fascination, romance memories, children, exclusivity/conflict style, flags, and the linked `actorId`. **Usage Notes:** Actor answers “who is this person in the world?”; RelationshipState answers “what is the player's romance/family relationship with this person?” Do not move all generic NPC state into RelationshipState. **Link:** [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts), [`src/relationships/relationshipController.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipController.ts).
- **`actorId` Identity Bridge `[NPC Identity / Adapter]`:** `actorId` is the intended bridge when the same durable person is represented by town/world content, a relationship candidate/state, or a combat/world entity. `ActorSystem` and `ActorRegistry.ensureRelationshipActor()` try to merge relationship state into an existing Actor when this ID is present. **Usage Notes:** Reuse the stable Actor ID when promoting an existing NPC into romance/combat/other systems. Do not silently create `relationship:<id>` or another identity if the same person already has an Actor. **Link:** [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts), [`src/actors/actorRegistry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorRegistry.ts), [`src/actors/actorFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorFactory.ts).
- **`portraitId` Presentation Hint `[NPC Presentation / Navigation Hazard]`:** The same `portraitId` field is carried through NpcProfile, TownResident, Actor, and Relationship records, but different UIs interpret it differently. Dating even uses `sage-1/2/3` as hints for selecting a full-sized portrait family. **Usage Notes:** Think “appearance hint/profile key,” not “path to the NPC portrait.” New presentation work should resolve through the appropriate surface instead of directly loading `portraitId`. **Link:** [`src/npcs/profiles.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/npcs/profiles.ts), [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/relationships/datingPortraitManifest.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/datingPortraitManifest.ts).

### NPC Dialogue & Interaction Layers

- **Legacy NPC Voice Selector `[NPC Dialogue / Legacy-Lightweight]`:** `selectNpcVoiceLine()` chooses short contextual NPC lines from role/biome/danger/health/flags/items/skills/snake-length conditions, and individual lines can supply a dialogue `portraitId`. **Usage Notes:** This is a simpler contextual chatter system. Before adding new general-purpose NPC dialogue here, check the richer Actor conversation system below. **Link:** [`src/npcs/npcVoice.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/npcs/npcVoice.ts).
- **Actor Conversation Selector `[Core / NPC Dialogue]`:** The Actor voice system selects talk/ask-around/ask-personal content from typed voice packs using Actor role/kind/species/personality, biome, hostility, relationship stage, health, memories, rumors, faction events, social links, soul/lore, recency, and player/world context. **Usage Notes:** This is the stronger reusable target for world-aware generic NPC conversation. Add reusable contextual NPC chatter to Actor voice packs rather than creating another selector. **Link:** [`src/actors/voice/voiceSelector.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/voice/voiceSelector.ts), [`src/actors/voice/voiceTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/voice/voiceTypes.ts).
- **Actor Speech Bubbles `[NPC Presentation]`:** Short in-world chatter/warnings are stored on `Actor.speech` with `createdAtMs`/`expiresAtMs` game-time lifetimes; renderers display only non-expired Actor-owned text. Social behavior, environment barks, and combat warnings set speech, with important/reactive speech separate from ambient bark limits. **Usage Notes:** Do not create renderer-owned NPC chatter timers when a durable Actor exists. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/scenes/snakeScene.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/scenes/snakeScene.ts).
- **Wanderer Encounter Content `[NPC Content / Encounter]`:** `WANDERER_ENCOUNTERS` defines authored one-off/repeating encounter cards with identity, zone/biome eligibility, small dialogue portrait hint, pages, choices, quest/card/score hooks, and encounter history. Active wanderer flags are promoted into stable Actors and rendered/materialized through the same Actor Presence world-body path as residents; encounter dialogue triggers from Actor proximity, not a timer-owned sprite. **Usage Notes:** Keep authored encounter text here, but put persistent identity, movement, speech, and memory through Actor System/Actor Presence. **Link:** [`src/npcs/encounters.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/npcs/encounters.ts), [`src/actors/actorFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorFactory.ts).
- **Actor Interaction Menu `[NPC Interaction / Capability Router]`:** Builds the generic inspect/talk/rumor/personal/quest/shop/romance/gift/apologize/pickpocket/threaten/parley/eat/spare/leave option model from Actor role, species, hostility, mood, opinions, combat state, and player capabilities. **Usage Notes:** New generic NPC verbs should usually surface here or through a capability consumed here rather than as scene-only click branches. **Link:** [`src/actors/actorInteractions.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorInteractions.ts).

### NPC Audit Findings

- **Dialogue Portrait Alias Gaps `[Audit Finding]`:** Legacy NPC voice content names portrait IDs such as `hunter-suspicious`, `cold-trapper-worried`, `jade-monk-neutral`, `badlands-ranger-neutral`, `goblin-clerk-suspicious`, and `forest-hermit-worried`, but `QuestPopup.resolvePortraitKey()` does not explicitly map them; unknown IDs fall back to `sage-1`. **Usage Notes:** Do not assume every authored `portraitId` has a distinct small portrait. Centralizing appearance aliases would make missing mappings visible. **Link:** [`src/npcs/npcVoice.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/npcs/npcVoice.ts), [`src/ui/questPopup.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/questPopup.ts).
- **Relationship Species -> Actor Species Adapter `[NPC Identity / Adapter]`:** `createActorFromRelationship()` maps every `RelationshipSpecies` into an `ActorSpecies`, including `goblin-angel` -> `goblinAngel` and `moleman` -> `moleman`. **Usage Notes:** Add new relationship species through `relationshipTypes.ts` and this typed adapter so the compiler forces the Actor-side mapping instead of silently degrading to `unknown`. **Link:** [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts), [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/actors/actorFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorFactory.ts).
- **Relationship Personality Source of Truth `[NPC Identity / Relationship]`:** `RelationshipState.personality` stores the resolved `RelationshipPersonality` used for dialogue, tag scoring, conflict style, exclusivity preference, rewards, and dating presentation. `RelationshipController.normalizeState()` fills this field for legacy saves, and romance Actor creation maps it into Actor personality tags beside `romantic/sentimental`. **Usage Notes:** New relationship behavior should read `state.personality` through controller helpers rather than re-hashing IDs or re-reading authored candidate profiles. **Link:** [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts), [`src/relationships/relationshipController.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipController.ts), [`src/actors/actorFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorFactory.ts).
- **Actor vs Relationship Social Metrics `[Audit Finding]`:** Actor mood/opinions and RelationshipState both carry concepts like trust, affection, fear, and resentment, but `ensureRelationshipActor()` mainly links flags/hostility/identity and does not directly synchronize the romance numeric state into Actor mood/opinions. **Usage Notes:** Generic Actor dialogue/interaction can therefore reason from different social values than the dating system unless the caller supplies relationship context explicitly. Define an adapter/sync policy instead of adding a third social score. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/actors/actorRegistry.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorRegistry.ts), [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts).
- **Actor Memory vs Relationship Memory `[Audit Finding]`:** Actors store world-event/social knowledge as `ActorMemory`; romances separately store `RelationshipMemory` for gifts, dates, proposals, marriage, neglect, betrayal, children, rivalry, death, etc. **Usage Notes:** Separate schemas are reasonable, but cross-domain events need an explicit bridge. Marriage, murder, betrayal, gifts, and major world events should not become visible to only one side accidentally. **Link:** [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts), [`src/actors/actorSystem.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorSystem.ts).
- **Structured Relationship Event Outcomes `[Relationship Presentation]`:** `RelationshipEventResult.outcome` can carry structured `tier`, portrait `mood`, and display `summary` metadata beside the human-readable message. `DatingScenePopup` consumes this metadata before falling back to legacy prose parsing. **Usage Notes:** New dating/relationship actions should set `outcome` when presentation needs semantic tier or mood; keep `message` editable prose, not a behavior contract. **Link:** [`src/relationships/relationshipTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipTypes.ts), [`src/relationships/relationshipController.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/relationshipController.ts), [`src/ui/datingScenePopup.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/ui/datingScenePopup.ts).
- **Town Resident Role Adapter `[NPC Identity / Adapter]`:** `TownResidentRole` is the shared typed role vocabulary for generated town residents, town role helpers, and Actor promotion args. `mapTownResidentRole()` in `actorFactory.ts` exhaustively translates that vocabulary into `ActorRole`, including specialized roles such as `gateGuard`, `guildContact`, and `blackMarketMerchant`. **Usage Notes:** Add new generated town roles to `townRoles.ts` first, then update the Actor adapter deliberately; do not accept a loose role string and let it degrade to `resident`. **Link:** [`src/world/townRoles.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/townRoles.ts), [`src/world/town.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/town.ts), [`src/actors/actorTypes.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorTypes.ts), [`src/actors/actorFactory.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/actors/actorFactory.ts).
- **Dating Portrait Family Coupled to Small Portrait Hint `[Navigation Hazard / Audit Finding]`:** Full dating portrait choice for human NPCs uses the candidate's `portraitId` (`sage-1/2/3`) to choose femme/masc/rogue portrait pools before hashing the ID. **Usage Notes:** This is intentional-looking compatibility glue, but it means changing a small dialogue portrait hint can also change a person's large dating appearance. Treat that coupling carefully until appearance identity is explicit. **Link:** [`src/relationships/datingPortraitManifest.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/relationships/datingPortraitManifest.ts).

## World Generation Engine, Interiors & Caves

### Normal Room Generation

- **Room Generation Pipeline `[World Engine]`:** Normal coordinate rooms execute ordered stages: biome map → multi-room structures → base terrain → room archetype → cross-room features → structures → random obstacles → vegetation → portals → safety validation. **Usage Notes:** New generation behavior should enter the appropriate stage rather than patch the top-level `generate()` flow. **Link:** [`src/world/generation/roomGenerationPipeline.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/generation/roomGenerationPipeline.ts).
- **Room Generation Context `[World Engine / Shared State]`:** Carries the room canvas, palette, archetype, structures, town membership, edge-access reservations, protected cells, transit stations, vegetation, and other stage outputs. **Usage Notes:** Stages should communicate through this context instead of parallel per-stage side stores. **Link:** [`src/world/generation/types.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/generation/types.ts).
- **Terrain Canvas `[World Engine Helper]`:** Bounds-safe mutable tile canvas with get/set/isEmpty/toRows plus hard entrance-runup clearing. **Usage Notes:** New generation stages should use this canvas where possible instead of writing another tile mutation wrapper. **Link:** [`src/world/generation/terrainCanvas.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/generation/terrainCanvas.ts).
- **Edge Access Plan `[World Engine Primitive]`:** Describes open room-edge corridors with side, center, width, runup depth, and reason; helpers derive protected cells, carve corridors, merge reservations, and validate clearance. **Usage Notes:** Structure doors, town gates/exits, bridges, forest mouths, and new cross-room features should reuse this contract rather than manually clear edge tiles. **Link:** [`src/world/generation/edgeAccess.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/generation/edgeAccess.ts).
- **Room Snapshot `[World Data Contract]`:** Shared generated-room representation carrying layout, portals, cave/layer entrances, structures, transit, cars, vegetation, biome/palette, cave/layer metadata, and landmark-specific data. **Usage Notes:** Reuse this contract for room-visible state rather than inventing side maps when the data is truly part of the room. **Link:** [`src/world/types.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/types.ts).
- **World Service Room Routing `[World Engine]`:** `WorldService` routes room IDs into normal coordinate generation, `layer:` generation, or cave generation and caches the resulting rooms/state. **Usage Notes:** This is the high-level boundary for “what kind of room is this?”; do not teach unrelated systems to parse every room subtype independently. **Link:** [`src/world/worldService.ts`](https://github.com/Sterfry42/snake-for-the-modern-gamer/blob/main/src/world/worldService.ts).
